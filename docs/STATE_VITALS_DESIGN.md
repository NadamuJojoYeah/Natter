# State & Vitals 插件设计

> **状态**：约束已定 · 实现待开工
> **日期**：2026-11-22
> **定位**：娱乐/角色类内容插件，opt-in，不进 WebConsole（管理面）。
> **关联**：[Harness 责任边界](HARNESS_RESPONSIBILITY.md)、[Prompt Compiler](PROMPT_COMPILER.md)、[会话控制台](CONVERSATION_CONSOLE.md)

---

## 0. 一句话

> 角色有「状态」和「数值」，它们被渲染成 prompt 片段去影响输出。**数值是内容的，机制是宿主的。**

这是一个**插件**，不是宿主能力。宿主只提供：prompt 片段贡献点、时钟、配置校验、可观测性。

---

## 1. 定位与边界

### 1.1 它是什么

| 组成 | 形态 | 例子 |
| --- | --- | --- |
| **state** | 离散、可枚举、带描述 | 饿 / 困 / 受伤 / 怀孕 |
| **vitals** | 连续、数值、随时间衰减 | 食欲 / 性欲 / 睡眠欲 |

两者都渲染成文本片段，进入 prompt 的指定位置。

### 1.2 它不是什么

- 不是宿主能力（不进 `src/` 的核心逻辑）；
- 不是运维视图（不进 WebConsole）；
- 不是记忆（见 §1.3）；
- 不是安全机制（内容由插件与配置负责，宿主不背书）。

### 1.3 与 memory 的分工

这条边界必须写死，否则会出现「用户的饥饿和角色的饥饿混在一起」：

| | 记谁 | 生命周期 | 作用域 |
| --- | --- | --- | --- |
| **memory** | 关于**用户**的持久事实 | 长期，显式记住 | 按会话 |
| **state/vitals** | **角色自己**的处境 | 短期，时间/事件驱动 | **全局**（见 §7） |

一句话：**memory 记你，state 记我。**

## 2. 五条早定格

以下五条后期修改代价极高（要迁移数据或改变 prompt 身份），必须现在锁定：

| # | 决定 | 为什么早定 |
| --- | --- | --- |
| 1 | 作用域 = **全局单一角色状态** | 决定存储主键；以后改要迁移全部历史 |
| 2 | 时间模型 = **衰减用墙钟**，存活类用单调时钟 | 混用会产生难查的诡异行为 |
| 3 | 持久化 = **插件自己的库文件** | 决定卸载/备份语义；进 `natter.db` 会破坏单一 schema owner |
| 4 | 入 prompt 方式 = **片段 + 分桶 + 位置靠后** | 决定 hash 稳定性与缓存命中率 |
| 5 | prompt 身份 = **存下来的文本 hash**，不是 state id | 决定缓存与可复现性 |

其余（衰减系数、阈值、档位名、文案模板、图表样式、UI 布局）全部**晚定格**，实现时再定，不会返工。

## 3. 数值模型

### 3.1 公式

统一为一阶滞后：

```text
v' = k * (target - v)
```

按 tick 离散化后：

```text
v_next = v + (target - v) * clamp(k * Δt, 0, MAX_STEP)
```

三个要点：

1. **乘性饱和**：增量是「到目标的剩余空间的**比例**」，不是固定差值。因此天然不越过目标、接近时自动变慢。
2. **Δt 夹紧**：离线三天时 `k*Δt` 可能远大于 1，会冲过 target 变负。必须把 `k*Δt` 夹到 `MAX_STEP`（建议 0.5~1.0）。
3. **target 泛化**：`target` 可以是上限（饥饿 → 100）、下限（饱腹感 → 0），或者是时间的函数（睡眠欲的昼夜曲线）。不要为每个 vital 写一套数学。

### 3.2 为什么不是加法 + clamp

```text
加法      v += rate * dt      会越过，只能靠 clamp 兜底；到顶瞬间生硬
乘性      v += (cap-v)*k*dt   自限、渐近、无需硬 clamp（但仍需夹紧 dt）
```

### 3.3 三个必须处理的细节

**① 渐近导致到不了端点**

`v` 会停在 99.7 而不是 100。因此：

- 阈值一律设在渐近线之下（85 就算 `starving`）；
- 或在 `(target - v) < ε` 时直接取端点。

推荐前者：阈值本来就不该贴着边界。

**② 多力合成必须一次性应用**

同一 tick 内有多个来源（自然衰减、事件效果、状态修正）。**先收集全部增量，再按 `(vitalId, sourcePriority)` 固定顺序一次性应用**。逐条顺序应用会引入顺序依赖，导致结果不可复现。

**③ 离线追赶的额外夹紧**

除了 `Δt` 上限，还要对单个 tick 的**总变化量**设上限，防止多个力叠加时单跳过大。

### 3.4 确定性要求

- 所有衰减计算必须走**注入的时钟**（`TimeProvider`），不得直接 `DateTimeOffset.UtcNow`；
- 浮点状态**不进入 prompt hash**（见 §4）；
- 测试必须能注入可控时钟做精确断言。

## 4. 分桶渲染：把连续数值变成稳定文本

这是让「数值平滑」和「prompt 稳定」共存的关键设计。

```text
内部   存浮点，衰减自然、曲线平滑
对外   只暴露「档位」：sated / peckish / hungry / starving
```

推论：

- 文本只在**跨档**时变化；
- 跨档是低频事件 → **prompt hash 只在跨档时变**；
- 因此 prompt 缓存命中率高（DeepSeek 的 `prompt_cache_hit_tokens` 可直接度量）；
- 图表仍然用浮点画，观感不受影响。

**档位定义必须单调、覆盖全区间、无空洞**（见 §9 校验）。

## 5. 状态如何进入 prompt

### 5.1 位置：靠后，但在最近对话之前

```text
人设 / 规则 / 世界观      ← 稳定，永不变
记忆摘要                  ← 低频变化
【状态片段】               ← 中频变化（跨档时）
最近对话                  ← 高频变化
```

理由：prompt 缓存按**前缀**匹配。状态放在前面会让每次跨档都使后面全部失效；放在中间偏后，损失最小，同时保留足够的近因权重。

### 5.2 片段契约

- 通过 `prompt.fragment` 贡献点提供；
- 片段 id 带插件命名空间（P3 已实现自动 `owner#local` 前缀）；
- **必须遵守每 provider 配额**（16 个片段 / 8000 字符），不能把 memory 或 library 挤出去；
- 插件不能声明 `Mandatory`、不能冒充 `HostBuiltin`（P3 已拒绝）。

### 5.3 渲染分档

```text
默认      短标签列表        [hunger: hungry] [energy: low]
刚变化    该状态写完整描述
高强度    超过高阈值的写完整描述
```

目的是让绝大多数回合只付出标签成本，把「小作文」留给真正值得注意的时刻。

## 6. 动态描述生成

### 6.1 方案

描述在**状态切换时生成一次**，随状态记录一起落库；状态持续期间复用同一份文本。

这既保留了表达多样性，又不破坏可复现性——**变化点是状态切换（低频），不是回合（高频）**。

### 6.2 四个硬性条件

| # | 条件 | 原因 |
| --- | --- | --- |
| 1 | **生成一次，存下来**，不得每轮重算 | 否则每轮 hash 变化，缓存与复现全部失效 |
| 2 | **存下来的文本参与 planHash** | 不是 state id，是文本本身的 hash |
| 3 | **生成失败必须降级**为模板文本，不阻塞回合 | 生成是模型调用，会超时/限流 |
| 4 | **必须幂等** | 状态切换可能被平台重投；按 `(stateId, transitionSeq)` 去重 |

### 6.3 内容约束

- 生成的文本必须落在该状态的**语义边界**内（「轻微饥饿」不能写成「濒死」）；
- 生成约束里带上状态的语义说明与档位；
- 保留模板作为「即使漂移也可接受」的兜底；
- 生成文本属于**内容**，宿主不背书、不做语义审查（见 Harness 责任边界）。

### 6.4 内容安全

- 片段正文**不进日志、不进审计、不进诊断包**（P3 的片段日志只记 id/code/count，已满足）；
- 需单独确认 `prompt explain` 与诊断包导出两个新出口不泄漏正文。

## 7. 作用域：全局状态 + 每会话记忆

### 7.1 决定

```text
state/vitals   全局单一：角色是「一个人」，跟谁说话都累
memory         按会话：但记得每个用户各自的事
```

这个组合恰好模拟真人：我累了跟谁都累，但我记得你。

### 7.2 两条硬约束

**① 全局状态是全局争用点**

跨平台/跨会话并发时会出现：

```text
两条都读到 hunger=50，都 +10，写回两次 → 60（应为 70）
```

必须**单写者或版本化 compare-and-set**：状态记录带 `Version`，切换走乐观并发，冲突重读重算。

**② 全局状态的描述必须去标识化**

全局状态会进入**所有用户**的 prompt。

```text
可以    "心情不错"
不可以  "被 A 夸奖后心情不错"     ← 等于把 A 的互动泄漏给 B
```

规则：**全局状态文本不得包含任何具体用户、会话、平台的信息**。需要「被谁影响」的层次只能放在 per-conversation 的内容里。

### 7.3 跨平台身份不是 bug

同一人在 Discord 与钉钉是不同 id。默认应视为**两个认识的人，但共享同一个角色状态**——真人也不知道这两个身份是同一个人。

身份关联（把多平台 id 绑成一人）是**独立的 opt-in 功能**，不放进第一版。

## 8. 存储

### 8.1 自己的库

```text
<state>/plugins/<plugin-id>/state.db
```

理由：

- `SqliteSchema` 是宿主**唯一**迁移 owner（task-38 刚统一），插件加表会重新制造双 owner；
- 卸载插件删目录即可，不留脏表；
- 可独立备份。

### 8.2 表结构要点

```text
state_snapshot    当前值 + Version + LastUpdatedAt + DefinitionVersion
state_events      变更流水（含 transitionSeq，用于幂等）
state_descriptions 生成的描述文本（按 state+档位+版本）
```

`DefinitionVersion` 必须存：作者改了衰减参数后，回看旧数据要用旧定义重算，否则会出现「用新参数解释旧曲线」的错乱。

## 9. 可扩展性：三层，不做 DSL

> 原则：**扩展数据，不扩展逻辑。**

### 第一层：声明式定义（覆盖约 90%）

```json
{
  "id": "hunger",
  "label": "饥饿",
  "range": { "min": 0, "max": 100 },
  "baseline": 0,
  "decay": { "mode": "multiplicative", "ratePerHour": 0.08, "target": 100 },
  "levels": [
    { "at": 0,  "id": "sated" },
    { "at": 30, "id": "peckish" },
    { "at": 60, "id": "hungry" },
    { "at": 85, "id": "starving" }
  ]
}
```

加一个新驱动 = 加一段 JSON，不需要写代码、不需要重新编译。

### 第二层：声明式效果（产生涌现）

```json
{ "at": 85, "id": "starving",
  "effects": { "energy": { "rateMultiplier": 1.4 }, "mood": { "bias": -12 } } }
```

**每条效果必须自己声明叠加规则**，不能全局默认：

| 规则 | 语义 |
| --- | --- |
| `add` | 相加 |
| `max` | 取绝对值最大 |
| `mul` | 相乘 |

三者在不同场景都对，必须逐条可选。

### 第三层：代码钩子（留一个口子）

JSON 表达不了的（例如「按最近 10 条消息的情绪算一个值」），留按名注册的接口：

```csharp
interface IVitalRule { ValueTask<VitalDelta> EvaluateAsync(VitalContext ctx); }
```

配置里按名字引用。95% 配置、5% 代码。

### 不建议的事

| 别做 | 原因 |
| --- | --- |
| 内嵌脚本引擎（Lua/JS） | 供应链、沙箱、调试三重负担 |
| 配置里求值任意表达式 | 不可静态校验 |
| 通用状态机 DSL | 表达力上去，可读性与可测性下来 |
| 为 N 维做完全泛化 | 实际只用 3–5 个 vital，过度泛化先坏可读性 |

### 必须有的校验

- `levels` 单调递增、覆盖 `[min, max]`、无空洞；
- `ratePerHour` 有合理上界；
- `effects` 引用的目标 vital 必须存在；
- 引用未注册的 rule 名 → **启动时报错**，不是运行时静默跳过；
- 定义本身有 schema 版本。

## 10. 审计与图表放哪

**按消费者拆，不按数据拆。**

| 消费者 | 需求 | 落点 |
| --- | --- | --- |
| 调参的人 | 多天曲线、参数对比 | **状态插件自己的页面** |
| 排查的人 | 第 N 轮时的状态 | **已有的 task trace / 会话时间轴**（一行摘要） |
| 追溯的人 | 变更流水 | 插件自己的事件表 |

### 三条原则

**① 主图表留在插件自己的页面**

状态是内容，WebConsole 是运维面。把角色状态曲线放进管理面，等于让管理面承载内容——与 Harness 责任边界冲突，也会逼管理面申请内容侧权限。

**② 轻量快照进已有时间轴**

排查场景不该让人跳两个页面。状态插件向 trace 贡献一行：

```text
hunger=72(hungry) energy=30(low) mood=+5
```

完整曲线点进去看。

**③ 不做跨插件读库**

会话控制台不要直接读状态插件的库。要联动就**深链接**（带 turn id 跳转）。跨插件读会立刻产生「谁的 schema、谁的迁移、谁负责脱敏」三连问。

### 图表实现

- **内联 SVG 手写折线**，不引图表库（与 WebConsole 保持同一取向：零依赖、零构建）；
- 数据分级保留：24h 内原始点 → 更早按小时聚合 → 超过 N 天只留档位变更事件。

## 11. 已知缺口：宿主侧需要补的东西

### 11.1 `PromptFragmentContext` 没有会话身份

当前形状：

```csharp
public sealed record PromptFragmentContext(
    RuntimeProfile Profile, string? PresetId, string? Locale,
    string Platform, string Protocol, ConversationKind ConversationKind,
    IReadOnlyDictionary<string, string> Variables);
```

**没有 source / conversationId / actorId**，也没有 `user.id`（`Variables` 白名单只有 `user.name`）。

后果：插件拿不到「我在跟谁说话」，§7 里的 per-conversation 相关内容做不了。

补充要求：

- **以可选 `init` 属性添加**（如 `ConversationScope? Conversation { get; init; }`），**不要改现有构造函数签名**——位置参数一变，所有既有 `IPromptFragmentProvider` 实现全部编译失败；
- 该属性为 null 时行为与现在完全一致；
- 补齐后 `PromptLibrary` 与既有片段测试不受影响。

### 11.2 宿主全局时钟

宿主应提供 `TimeProvider` 单例，插件注入使用；插件在拿不到时应回落到 `TimeProvider.System`，不得因此激活失败。

### 11.3 日志与导出出口复核

P3 保证片段正文不进日志。但**后来新增的两个出口要单独确认**：

- `prompt explain` 输出；
- WebConsole 诊断包导出。

两者都不得带出状态描述正文。

## 12. 非目标

- 不做跨平台身份关联（独立 opt-in 功能）；
- 不内置脚本引擎；
- 不做内容审查（Harness 不背书内容）；
- 不做真实平台消息发送；
- 不接管 memory 的职责；
- 不做多角色并发持有多个状态集（第一版单角色）。

## 13. 验收标准（第一版）

- [ ] 数值衰减走注入时钟，测试可用可控时钟精确断言；
- [ ] `Δt` 与单跳变化量均有上限，离线一周不会出现越界值；
- [ ] 渲染按档位分桶，浮点不进 prompt hash；
- [ ] 跨档才改变 planHash，同档内多轮 hash 稳定（用两次采样对比断言）；
- [ ] 描述生成一次后落库，重投不重复生成，失败降级为模板且不阻塞回合；
- [ ] 全局状态写入有版本化保护，并发两路不丢更新；
- [ ] 状态文本不含任何用户名/会话 id（用哨兵断言）；
- [ ] 插件使用自己的库文件，未向 `natter.db` 增表；
- [ ] 声明式定义的校验覆盖：档位单调/覆盖/无空洞、效果引用存在、未知 rule 名启动报错；
- [ ] 片段遵守每 provider 配额，不挤占 memory 与 library；
- [ ] 日志、`prompt explain`、诊断包导出均不含状态正文；
- [ ] 默认不启用；未安装该插件时宿主行为零变化。

---

## 14. 一句话总结

> 数值用「乘性饱和 + dt 夹紧」，文本用「分桶」，作用域用「全局状态 + 每会话记忆」，扩展用「声明式数据 + 一个代码钩子」，视图用「插件自己画 + 快照进已有时间轴」。
