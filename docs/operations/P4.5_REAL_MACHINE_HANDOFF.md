## 2. systemd 实机部署

以下命令在目标机 root/sudo 下执行。

### 2.1 发布

```bash
dotnet publish src/Natter.Cli/Natter.Cli.csproj \
  -c Release \
  -o /opt/natter \
  /p:UseAppHost=false
```

### 2.2 安装布局和 unit

```bash
sudo deploy/systemd/install.sh \
  --release /opt/natter \
  --config-src config \
  --start
```

脚本会：

- 创建 `natter` 系统用户；
- 创建 `/etc/natter/config`；
- 创建 `/etc/natter/live.env` 空模板（0600）；
- 创建 `/etc/natter/proxy.env`（0640）；
- 创建 `/var/lib/natter`、`/var/log/natter`（0700）；
- 安装 `natter.service`；
- 安装并启用 `natter-soak.timer`；
- 可选启动服务。

### 2.3 填 secret

```bash
sudoedit /etc/natter/live.env
sudo chmod 600 /etc/natter/live.env
sudo chown root:root /etc/natter/live.env
```

不要用 `echo` 把 secret 写进 shell history。

### 2.4 出口

推荐直连：

```bash
sudoedit /etc/natter/proxy.env
```

保持：

```text
NO_PROXY=127.0.0.1,localhost,::1
```

如果必须代理，填入 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`，但必须满足 Discord interaction 3s 预算；参考 [Discord 3s 出口](discord-3s-interaction-egress.md)。

### 2.5 启动

```bash
sudo systemctl daemon-reload
sudo systemctl restart natter
sudo systemctl status natter --no-pager
journalctl -u natter -n 100 --no-pager
```

### 2.6 基础验收

```bash
curl -s http://127.0.0.1:5099/health | jq
sudo deploy/systemd/verify.sh \
  --evidence artifacts/ops/p4.5/handoff/systemd-$(date +%F)
```

预期：

- `systemctl is-active natter` = active；
- `/health` HTTP 200；
- `status=healthy`（Tier1-only 部署允许）；
- `plugins.failed=0`；
- `upstreams[].connected=true`；
- `live.env` 0600；
- state 0700；
- DB `integrity_check=ok`。

### 2.7 生命周期

```bash
sudo systemctl restart natter
sudo systemctl stop natter
sudo systemctl start natter
```

记录：

- 停止是否 10s 内退出；
- 重启后是否恢复 `connected=true`；
- memory/session 是否保留。

## 3. 真实 P5 命令矩阵

要求：Discord 命令在 **3 秒内 ACK**；如果出现“应用未响应”，先查出口 RTT，不要先改代码。

在测试 guild/频道执行：

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| M-1 | `/task prompt:用一句话说明你能做什么` | ephemeral `Task accepted: task_...` |
| M-2 | 等任务完成 | 结果回原频道，只一条 |
| M-3 | `/status task:<id>` | 显示 Completed、version、结果摘要 |
| M-4 | `/tasks` | 只列当前 session active；完成后为空 |
| M-5 | 起一个长任务，执行 `/cancel task:<id>` | 取消成功，频道只出现一条结果 |
| M-6 | 用另一个账号 `/cancel` 同一 task | 被拒绝，不能取消 |
| M-7 | `/ask prompt:test` | 正常回复，不增加 tasks.created |
| M-8 | 任务执行中重启 serve | 不出现第二条结果；重启后状态合理 |
| M-9 | 真实长任务 >2 分钟 | 不被 watchdog 误判 Expired |
| M-10 | DM 和 guild @bot 各一条 | 正常回复，不串会话 |
| M-11 | DingTalk 群 @bot 一条 | 文本正常回复 |
| M-12 | 重启后 `/memory` | memory/session 保留 |

记录每条的：

```text
时间
命令
task id
ACK 时间
结果
health 计数
```

## 4. 24h 被动 soak

### 4.1 启动

systemd 安装脚本已启用 timer：

```bash
systemctl list-timers natter-soak.timer
```

或手动启动一个采样循环：

```bash
scripts/soak-sample.sh \
  -o /var/log/natter/soak-$(date +%F).jsonl \
  -i 300 \
  -d 86400
```

要求机器 24h 不休眠。

### 4.2 中途巡检

```bash
curl -s http://127.0.0.1:5099/health | jq
tail -n 5 /var/log/natter/soak-$(date +%F).jsonl
systemctl status natter --no-pager
```

不要用 `natter health` cron；它会新建 gateway 会话。用 loopback `/health`。

### 4.3 结束后审计

```bash
python3 scripts/soak-report.py /var/log/natter/soak-*.jsonl --interval 300
```

通过标准：

- coverage ≥ 95%；
- 无意外 gap（机器休眠不算通过）；
- `restarts` 有解释；
- 新载荷 `silent disconnect` = 0，或每条有 `lastDisconnectError/Code` 说明；
- `sendFailures` 不增长；
- DB/WAL 无异常增长；
- 无重复回复。

如有告警：

```bash
scripts/ops-health-alert.sh --health-json <snapshot.json>
```

## 5. secret 轮换

### 5.1 检查

```bash
scripts/rotate-secret.sh --file /etc/natter/live.env --check
```

### 5.2 轮换

在平台控制台重置一个 key，然后：

```bash
printf '%s' "$NEW_VALUE" | scripts/rotate-secret.sh \
  --file /etc/natter/live.env \
  --key DISCORD_BOT_TOKEN
```

要求：

- 值不从命令行参数传入；
- 生成 0600 备份；
- 只改目标 key；
- 重启：

```bash
sudo systemctl restart natter
curl -s http://127.0.0.1:5099/health | jq
```

### 5.3 验收

- 新 key 生效；
- 旧 key 在平台侧失效；
- 日志无 secret；
- 回滚备份可用。

## 9. 常见问题

### `/task` 显示“应用未响应”

先看：

```bash
curl -s http://127.0.0.1:5099/health | jq '.upstreams[] | select(.source|startswith("discord"))'
```

如果 `lastError` 含：

```text
interaction_defer_failed
```

说明 3s ack 预算不够，不是 P5 代码问题。检查出口 RTT。

### health 500 / MissingMethodException

插件 lib 与 host 不同源。重新 staging：

```bash
scripts/stage-tier1-plugins.sh -o /opt/natter/plugins --host-dir /opt/natter
```

要求 `hostParity.mismatches=0`。

### 24h soak gap

机器休眠、服务重启、timer 未运行都会造成 gap。
不要用“补采样”伪装 24h 通过；重新计时。

### Docker 能跑，systemd 不能

两个形态分别验收；Docker 通过不等于 systemd 通过。
