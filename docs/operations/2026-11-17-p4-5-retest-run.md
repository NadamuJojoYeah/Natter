## 4. 具体问题（本轮新增）

### OBS-015 · phase 反映调用点，不等于真实网络阶段

- **现象**：`NO_PROXY=discord.com`（bypass → 直连不可用）时报 `phase 'identify_ready'`，而不是 `rest_gateway` / `ws_connect`。
- **原因**：`phase` 变量在 `ConnectAsync` 的 await 点推进；`LoginAsync` 不触网、`StartAsync` 立即返回，后台连接失败只能表现为 READY 超时。
- **影响**：排障时 phase 会误导（看起来 REST/WS 都成功了）。
- **建议**：phase 取自 Discord.Net 的连接状态/最后一次错误，或在 message 中附带 `Disconnected` 事件的异常。

### OBS-016 · 静默断连的 `lastError` 仍为 null

- **现象**：两处现场都只有时间戳没有原因：① 接手时 4.6h 断连（`lastDisconnectAt=09:21:54Z`、`reconnectCount=2`）；② 本轮常驻实例启动 1.5 分钟后再次断连（`lastDisconnectAt=09:33:05Z`、`reconnectCount=2`，10s 后仍未自愈），两处 `lastError` 均为 `null`。
- **影响**：能看到“断了”，看不到“为什么”。
- **建议**：断连时把 `Disconnected` 事件/重连异常的脱敏消息写入 `lastError`。

### OBS-017 · duration 取消时失败信息退化为 `A task was canceled.`

- **现象**：坏代理 `--duration 60` 到点取消，`upstream-connect-failed` 的 message 变成 `A task was canceled.`，不再带 phase。
- **影响**：合法取消与真实失败在日志中难以区分。
- **建议**：取消路径单独标 `canceled`（或保留 phase），与失败原因分开。

### OBS-018 · `sendFailures` 缺受控注入手段

- **现象**：字段已暴露，但无 Manage Channels 权限时无法制造一次真实发送失败。
- **建议**：提供测试用 `--fail-send`/CLI 注入，或允许向已删除频道发送的受控用例。

### FLAKE-001 · SendFailureProbeTests 首次运行无法找到 discord upstream

- **现象**：第 1 次运行等待 90s 后 `registry.Upstreams` 无 discord（`Sequence contains no matching element`），第 2 次 7s 通过。
- **影响**：单次失败不能判定 `sendFailures` 缺陷；live 用例需要重跑策略。
- **建议**：live 测试增加一次重试或预热（先跑 `plugins list` 确认 staging 完成），并在失败时输出插件 Failed 详情。
