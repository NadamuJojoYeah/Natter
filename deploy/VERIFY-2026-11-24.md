# 部署验证 · rel-2026-11-24

这次改动很大：**插件 id 全改、契约程序集拆了两个、前端重写成 React、schema 到 v8、诊断输出加了脱敏装饰器**。

所以这份清单只验证**这次真正变了的东西**，不是通用验收。

## 0. 部署前必须先做一件事

实机 `/opt/natter/plugins/` 现在还是**改名前的目录名**（先自己 `ls` 看一眼实际有哪些）：

新产物用的是完整 id（`natter.feature.ai.deepseek/` 这种）。**两套目录同时存在 → 同 id 两个目录 → `duplicate-plugin-id` → 插件全挂。**

所以必须先把旧目录移走：

```bash
cd ~/Projects/csharp/Natter

# 1. 备份现有部署
sudo mkdir -p /var/backups/natter/pre-rel-2026-11-24
sudo tar -C /opt -czf /var/backups/natter/pre-rel-2026-11-24/opt-natter.tar.gz natter
ls -lh /var/backups/natter/pre-rel-2026-11-24/opt-natter.tar.gz

# 2. 停服
sudo systemctl stop natter.service

# 3. 把旧插件目录移到备份区（不删，以便回滚）
sudo mkdir -p /var/backups/natter/pre-rel-2026-11-24/old-plugins
sudo mv /opt/natter/plugins/* /var/backups/natter/pre-rel-2026-11-24/old-plugins/
ls /var/backups/natter/pre-rel-2026-11-24/old-plugins/
```

**预期**：`/opt/natter/plugins/` 变空，旧目录都在备份区。

## 回滚

如果第 2 步就起不来：

```bash
sudo systemctl stop natter.service
sudo rm -rf /opt/natter/plugins/*
sudo mv /var/backups/natter/pre-rel-2026-11-24/old-plugins/* /opt/natter/plugins/
sudo tar -C /opt -xzf /var/backups/natter/pre-rel-2026-11-24/opt-natter.tar.gz --overwrite
sudo systemctl start natter.service
```

**注意**：代码可以回滚，但 **schema 已经是 v8，不会自动回到 v7**。旧代码读 v8 库会静默失去 memory FTS（返回空，不报错）。所以回滚后记忆检索会失效。

## 本次部署踩到的三个坑（下次同类改动前先看）

### ① 插件 id 改名会静默孤儿化外部配置

配置解析规则是 `<NATTER_CONFIG_DIR>/<manifest.id>.json`。改 id 后旧文件名对不上：

```text
插件带着「没配置」的状态激活，报 invalid-config: /token property is missing
像是代码 bug，实际是配置没找到
```

`update-release.sh` 现已加检测：部署前扫描配置目录，列出「文件名不匹配任何新 id」的文件并给出改名指令。你也可以手动跑：

```bash
sudo deploy/update-release.sh --release <产物> --dry-run --config-dir /etc/natter/config
```

### ② 增量构建会留下已消失的依赖

契约程序集拆分后，`bin/Release/net10.0/lib/` 里仍留着旧的 `Natter.Application.dll`，staging 的 hash 校验会拒绝部署：

```text
host/plugin assembly mismatch — refusing to hand out an inconsistent plugin root
```

**修复**：改动程序集结构后，先清掉受影响的插件构建产物再 staging：

```bash
rm -rf samples/Natter.Sample.Plugin.Discord/{bin,obj} \
       plugins/Natter.Plugin.PromptLibrary/{bin,obj}
```

### ③ AntD 的样式是运行时注入，CSP 必须放行

AntD v5 用 CSS-in-JS，构建产物里**没有 .css 文件**。旧 CSP 的 `style-src 'self'` 会拦掉全部样式——页面功能正常但完全没有外观。

已改为 `style-src 'self' 'unsafe-inline'`。`script-src` 仍为 `'self'`，`img/connect/font` 仍为 `'self'`，注入的 CSS 无法外传。
